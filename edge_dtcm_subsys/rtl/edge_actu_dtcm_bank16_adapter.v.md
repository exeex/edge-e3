# edge_actu_dtcm_bank16_adapter.v

## Purpose

`edge_actu_dtcm_bank16_adapter` bridges the ACTU unit's simple 128-bit DTCM
beat interface onto the native 16 x 64-bit SRAM-bank lower path. It is owned by
`edge_dtcm_subsys_core` and is selected instead of the tensor native client when
ACTU is active.

## Interface

- `rd_req/rd_ready/rd_addr` issues one 128-bit read beat at a DTCM 64-bit word
  address.
- `wr_req/wr_ready/wr_addr/wr_wdata/wr_wstrb` issues one 128-bit write beat.
- `rd_rvalid/rd_rdata` returns the read beat one cycle after an accepted read.
- `lower_owned_mask` is the current lower-path bank ownership mask generated by
  the DTCM arbiter/fabric phase.
- `bank_*` are native per-bank SRAM-door commands.

Writes have priority when read and write are asserted in the same cycle. The
current ACTU IO unit never needs simultaneous read/write acceptance to sustain
the one-element pipeline because it buffers input and output separately.

## Addressing

ACTU addresses are DTCM 64-bit word addresses. A 128-bit beat touches
`addr[3:0]` and `addr[3:0] + 1`, with SRAM row
`addr[SRAM_ADDR_WIDTH+BANK_INDEX_WIDTH-1:BANK_INDEX_WIDTH]`.

The adapter only accepts a request when both target banks are present in
`lower_owned_mask`. Sequential aligned beat addresses naturally alternate with
the lower-path mask after initial phase lock, allowing one 128-bit beat per
cycle.

## Non-Goals

This block is not a general DTCM arbiter. It does not issue upper-path LSU/DMA
traffic, does not own tensor scheduling, and does not support unaligned 128-bit
beats that cross an SRAM row boundary. The ACTU IO contract emits aligned
128-bit beats for BF16 streams.

## Tests

Local coverage is provided through `edge_dtcm_subsys_core`/`edge_core_top`
integration tests once ACTU is connected. Unit-level tests may be added if the
adapter grows independent scheduling policy.
