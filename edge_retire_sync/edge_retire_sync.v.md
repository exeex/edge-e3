# edge_retire_sync.v

## Scalar M completion

`complete6_*` is the scalar RV64M completion source. Retirement still selects
the oldest completed entries, independent of fast/M execution finish order.

The focused multi-retire test also fills all eight entries behind an unfinished
oldest load, completes interleaved store/MUL/fast-ALU work out of order, proves
full-queue allocation backpressure, and verifies two-wide age-ordered drain
with same-cycle refill after the oldest load completes.

## Purpose

Maintain a single in-order architectural retirement stream while scalar, Edge
Vector, and Edge Tensor execution proceed concurrently.

This block is the proof point that the design is not SMT and not out-of-order
retire. There is one program order, represented by sequence ids generated by the
predecoder.

Implemented file:

```text
edge_retire_sync/edge_retire_sync.v
```

The first RTL slice is a power-of-two-depth in-order retire queue with:

```text
ISSUE/ALLOC WIDTH = 2
COMPLETE PORTS   = 6
RETIRE WIDTH     = 2
```

The word "queue" means program-order FIFO storage, not one-retire-per-cycle.
The head may dequeue two adjacent done entries in the same cycle.
The two-bit allocate/retire counts are zero-extended before pointer arithmetic;
owners may instantiate deeper queues such as 64 entries without polluting
head/tail with out-of-range count bits.

## Parameters

```text
DEPTH
SEQ_ID_WIDTH
EPOCH_WIDTH
KIND_WIDTH
```

`DEPTH` is expected to be a power of two in this first implementation so head
and tail pointer truncation gives natural wraparound.

## Inputs

From scalar pipe:

```text
alloc0_valid
alloc0_seq_id
alloc0_epoch
alloc0_kind
alloc0_serializing
alloc1_valid
alloc1_seq_id
alloc1_epoch
alloc1_kind
alloc1_serializing
alloc_ready
```

`alloc0` and `alloc1` are the two program-order entries accepted from the
frontend/predecoder in one cycle. If `alloc1_valid` is asserted,
`alloc0_valid` must also be asserted; the first slice does not support a hole in
the allocate pair. `alloc_ready` is high when there are at least two free slots
after considering any same-cycle retire dequeue. This conservative worst-case
rule keeps `alloc_ready` independent of the current cycle's `alloc*_valid`
signals, so owners can feed it back into issue readiness without creating a
ready/valid combinational loop.

From execute units:

```text
complete0_valid
complete0_seq_id
complete0_epoch
...
complete5_valid
complete5_seq_id
complete5_epoch
```

The seven complete ports are generic done events. They cover concurrent scalar,
vector, ordinary tensor-command, and tensor-start launch completion sources
without a lossy priority mux. A complete event marks the matching allocated
`seq_id/epoch` entry done; it does not by itself retire the entry.

From global control:

```text
redirect_kill_valid
redirect_kill_seq_id
redirect_kill_epoch
```

Redirect kill clears valid entries in the matching epoch whose nonzero modulo
sequence distance from `redirect_kill_seq_id` is in the forward half of the
sequence space. This preserves younger ordering across `seq_id` wraparound;
the eight-entry queue is far smaller than that half-range.

`alloc_ready` is low throughout a redirect cycle. Kill processing can rewind
the tail, so corrected-path allocation retries on the following cycle against
the updated tail instead of writing at the stale pre-redirect position.

Because scalar and tensor completion/allocate paths may arrive in different
cycles, redirect can clear the physical head while leaving other live entries.
Such an invalid physical head is skipped without decrementing the live-entry
count. It is not reported as a retirement event.

Queue occupancy drops for every killed entry, but the allocation tail rewinds
only across the contiguous killed suffix immediately before the old tail.
Killed entries elsewhere remain physical holes; rewinding across them would
make the tail point at a surviving entry when allocation order differs from
sequence age.

Allocation readiness checks both physical write slots in addition to aggregate
free count. A slot is writable when invalid or when that exact slot retires in
the current cycle. This preserves full-queue retire/refill throughput while
blocking a fragmented queue whose `tail` or `tail+1` still contains a survivor.

The queue must also be compact before accepting allocation: all `count` live
entries must occupy the consecutive circular range starting at `head`, and
`tail` must equal `head + count`. A non-suffix redirect kill may leave holes;
retirement and one-slot head-hole skipping continue, but allocation remains
blocked until the head advances through the holes and the surviving range is
compact again. This prevents a two-wide refill across a retiring head from
placing lane1 ahead of older survivors.

## Outputs

```text
retire0_valid
retire0_seq_id
retire0_epoch
retire0_kind
retire1_valid
retire1_seq_id
retire1_epoch
retire1_kind
debug_valid
debug_done
debug_count
```

The ordered `retire0/1_*` outputs are present in production as well as debug
builds because they are architectural feedback to the committed store buffer.
Only the bitmap/count observation ports remain conditional on `EDGE_DEBUG`.

`retire0` is the current head when it is valid and done. `retire1` is the next
entry only when `retire0` is also valid, the head is not serializing, and the
next entry is valid and done. A serializing head retires by itself and blocks
same-cycle retirement of the following entry. Redirect kill has priority over
retire dequeue; the kill cycle clears younger matching-epoch entries, and any
surviving done head retires on a later cycle.

## Current RTL Port Mapping

The current generic kind encoding is local to the owner until the predecoder/top
wiring lands:

```text
0: SCALAR_NORMAL
1: VECTOR_TOKEN
2: TENSOR_TOKEN
3: VECTOR_SYNC or serial placeholder
```

## Retire Entry Kinds

```text
SCALAR_NORMAL
  Normal scalar instruction.

VECTOR_TOKEN
  One retire-visible entry per Edge Vector instruction. Retire waits for vector
  done, including completion of any vector DTCM request owned by that command.
  GPR/FPR operand capture is sideband readiness state and does not create a
  separate retire entry.

TENSOR_TOKEN
  One retire-visible entry per Edge Tensor DMA/Tensor instruction. For
  nonblocking commands such as `dma.start` or `tensor.start`, retire waits for
  command acceptance and required descriptor snapshot, not for transfer/compute
  completion. For `dma.sync` and `tensor.sync`, retire waits for true engine
  completion.

VECTOR_SYNC
  User-visible `vector.sync` wait instruction. The predecoder creates both this
  retire-visible scalar entry and a matching vector-side barrier entry with the
  same sync id. Retire waits for the matching vector ack, which means older
  vector commands and their DTCM effects are complete, before allowing scalar
  software to proceed. Branch-control `CONTROL_DEP` entries are queue dependency
  tokens, not retire-visible entries. DMA/Tensor sync instructions are Edge
  Tensor commands and retire through `TENSOR_TOKEN`.
```

## Retire Rule

```text
if redirect_kill_valid:
  retire no entries
else if head is valid and done:
  retire0 = head
  if head is not serializing and next is valid and done:
    retire1 = next
else:
  retire no entries
```

Younger scalar instructions may execute before an older vector or tensor token
completes, but they must not retire before that older token.

Execute completion can arrive before an entry reaches the head. It only sets the
entry's `done` bit. Architectural retirement happens only when that done entry
is the in-order head, or the second consecutive done entry behind a non-
serializing head.

## Simulation Error Rule

The first RTL slice does not implement architectural exceptions, traps,
interrupts, debug halt, or breakpoint handling. Unsupported
scalar/vector/tensor states should fail simulation in the detecting module or
testbench.

```text
if unsupported_state_detected:
  assert or $fatal
  fail the simulation
```

## Branch And Redirect/Kill Rule

Branches are resolved by the scalar/control side. The retire/sync block provides
the final architectural ordering point:

- Correct-path instructions retire in sequence order.
- Wrong-path vector and tensor commands are killed by redirect `epoch/seq_id`
  boundary.
- No vector writeback may become architectural after its token is killed.
- No DMA/Tensor command may become visible after its token is killed.

## First Implementation Simplification

The first implementation may let younger scalar work execute through scalar
rename/checkpoint state while vector issue waits behind unresolved scalar
control boundaries. Later implementations can allow deeper speculative vector
execution only if they add the required vector-side buffering, rename, or
writeback isolation. The same applies to deeper speculative tensor execution:
descriptor rollback, DMA rollback, or visible-command isolation would be needed
before tensor issue could run ahead of unresolved scalar control.

The first RTL slice is not yet wired into the frontend/scalar/vector/tensor top.
It does not carry register writeback payloads, exception payloads, PC/length
metadata, or CSR side effects. Those remain in owning pipes for now and should
move toward this architectural retire boundary when the top-level integration
switches from execute-complete pulses to retire slots.

## Local Tests

```text
edge_retire_sync_multi_retire_tb
edge_retire_sync_random_tb
```

The local proof covers:

- two done head entries retire in the same cycle
- a younger done scalar entry cannot retire past an older not-done vector token
- a serializing head retires alone even when the next entry is done
- redirect kill removes younger same-epoch entries
- redirect-created head holes are skipped without losing live entries
- a full queue holds interleaved younger store/MUL/ALU/load completions behind
  an incomplete oldest load, rejects allocation without moving its tail, then
  drains and refills two-wide in strict age order
- an eight-seed random scoreboard compares two-wide allocation, seven
  completion sources, serializing retirement, redirect kills, backpressure,
  and sequence wraparound against an independent ordered reference queue for
  2000 cycles per seed
- random coverage bins require full rejection, retire/refill overlap,
  redirect/allocation overlap, wraparound redirect, seven active completion
  ports, serializing lane-1 blocking, head holes, and oldest-incomplete blocking
- cycle invariants require occupancy to equal the valid-bit population, done to
  imply valid, live tags to be unique, a non-full tail slot to be free, and a
  rejected full-queue allocation to preserve all queue state
- a directed fragmented interleaved-survivor case requires pair allocation to
  wait unless both physical tail slots are writable; the random test also
  reports any naturally encountered fragmentation blocks
- a directed late-completion case reuses a killed sequence ID in a new epoch
  and proves that the stale old-epoch completion cannot mark it done
- each random seed injects stale wrong-epoch completions for a live sequence;
  coverage requires those events while the scoreboard proves they do not mark
  the live entry done
